# 注意事項清單：資料適不適合用這個方法

階段 4 判斷時用。對照 `check.json`（叢集數、叢集大小、不一致對數、缺失、各時間點比例）和 `profile.json`（變數型態、資料結構），替每個候選方法標示：

- ✅ 可以使用
- ⚠️ 可以使用，但需要提醒（說明問題與要用的方法）
- ❌ 不適合使用（說明原因，建議其他方法或轉介）

使用規則（和 Part 1 相同）：

- 標有 **【MVP】** 的條目是第一版的核心 guardrails，會直接影響 ✅／⚠️／❌。
- 標有 **【文字提醒】** 的條目只寫進說明，不改變方法的主要標示。
- 「需要向使用者確認」的條目，資料無法證明，一定要問，不可以自己假設。
- **沒有列在這份清單上的狀況，不要自己發明標準或門檻**；看到可疑的地方就說出來並問使用者。
- 課本沒有給數字門檻的地方，本清單也不給；只呈現數字讓使用者判斷。

## A. 資料結構（一定要先確認）

### 1. 資料是否真的不獨立【MVP】

- **狀況**：使用者沒有說明每一列的關係。
- **為什麼要注意**：本 Skill 的方法是為了不獨立的資料設計的；資料其實獨立時，應該用 Part 1／Part 2 的方法，結果更簡單、檢定力也較好。反過來，不獨立的資料用獨立的方法，SE 會錯（§8 開頭、§9 開頭）。
- **做法**：一定要問。`profile.json` 的 `structure.hints` 只是線索。
- **Skill 是否能自動判斷**：Partial。能偵測重複的 id、類別相同的成對欄位，但無法證明。

### 2. 叢集 id 不明【MVP】

- **狀況**：沒有 id 欄，或有好幾個可能的 id 欄。
- **做法**：寬格式一人一列時，由程式依列號產生 id，並在確認清單寫明；長格式沒有 id 時 ❌，請使用者提供，不可以自己猜。
- **Skill 是否能自動判斷**：Partial。

### 3. 配對資料兩次的類別不同【MVP】

- **狀況**：例如第一次 1–5 分、第二次 1–4 分；或兩欄的類別名稱不一致。
- **為什麼要注意**：邊際同質性要比較同一組類別的兩個分布，必須是方陣（§8.3）。
- **標示與做法**：A 類方法 ❌。類別名稱只是寫法不同時，請使用者確認對應方式後，由程式 `recode`。
- **Skill 是否能自動判斷**：Yes。

### 4. 寬格式要轉長格式【MVP】

- **狀況**：重複的測量放在不同欄（`G1`、`G2`、`G3`）。
- **做法**：✅ 由 `scripts/reshape.R` 轉換，並把轉換設定（哪幾欄、時間怎麼編碼）寫進 `spec.json`。**不讓 Claude 手動轉。**
- **Skill 是否能自動判斷**：Partial。能偵測類別相同的欄位，但要問使用者這些欄位是不是同一件事的重複測量。

## B. 配對比較（A 類方法）

### 5. McNemar 的不一致對數太少【MVP】

- **狀況**：n* = n₁₂ + n₂₁ ≤ 10。
- **為什麼要注意**：McNemar 的 z 檢定用常態近似二項分配，課本建議 n* > 10 時才用（§8.1.1）。
- **標示與做法**：McNemar χ² 標 ⚠️，改以**精確二項檢定**（n₁₂ ~ Bin(n*, 0.5)）為主。
- **Skill 是否能自動判斷**：Yes。

### 6. 不一致對數為 0【MVP】

- **狀況**：n₁₂ = 0 或 n₂₁ = 0。
- **為什麼要注意**：條件勝算比 n₁₂/n₂₁ 會是 0 或 ∞（§8.2.4）。
- **標示與做法**：⚠️ 一定要呈現原始次數；條件勝算比報告為 0 或 ∞，不加 0.5。n₁₂ + n₂₁ = 0 時無法檢定，直接說明兩次完全相同。
- **Skill 是否能自動判斷**：Yes。

### 7. 準對稱模型有 0 次數的對角外格子【文字提醒】

- **狀況**：某一對 (i, j)、(j, i) 都是 0。
- **為什麼要注意**：那一對沒有資訊；準對稱模型仍可配適，但部分參數可能無法估計。
- **做法**：說明哪些類別配對沒有觀察值。
- **Skill 是否能自動判斷**：Yes。

### 8. 有序結果卻用名目方法【MVP】

- **狀況**：使用者確認結果有序，但要求名目的邊際同質性檢定。
- **為什麼要注意**：名目檢定 df = c − 1，有序方法 df = 1、通常檢定力高得多（§8.4）。
- **標示與做法**：名目方法 ⚠️，推薦有序方法；使用者堅持時可以做，但兩者都報。
- **Skill 是否能自動判斷**：Yes（在使用者確認型態之後）。

## C. 模型（B 類方法）

### 9. 叢集數少【文字提醒】

- **狀況**：叢集（人）的數目不多。
- **為什麼要注意**：GEE 的 robust SE 只在大樣本下可靠，小樣本時傾向低估（§9.2.4）。課本**沒有給門檻**。
- **做法**：一律報告叢集數；說明 robust SE 的這個性質。**不要自己訂一個數字當門檻。**
- **Skill 是否能自動判斷**：Yes（數字）；夠不夠多要使用者判斷。

### 10. 叢集大小為 1 的叢集【文字提醒】

- **狀況**：有些叢集只有 1 筆（例如缺考兩次）。
- **為什麼要注意**：這些叢集對「叢集內」效果（時間、情境）沒有資訊。
- **做法**：報告叢集大小的分布，以及有幾個叢集只有 1 筆。
- **Skill 是否能自動判斷**：Yes。

### 11. 叢集大小不一或缺少某些時間點【MVP】

- **狀況**：有人缺了某次測量。
- **為什麼要注意**：GEE 只用到觀察到的資料，需要缺失**完全隨機**（MCAR）才不會有偏誤；GLMM 用最大概似，只需要**隨機缺失**（MAR，缺不缺可以和已觀察到的資料有關）（§9.5.1）。
- **標示與做法**：
  - 有缺失：一律報告每個時間點的人數、缺了幾筆。
  - 缺失 ≥ 5%：GEE ⚠️，說明 MCAR 的假設；若同時配 GLMM，說明 GLMM 的假設較弱。
  - 缺失 ≥ 20%：加強提醒。
  - 不因缺失比例高就標 ❌；不做多重插補（§9.5.2*，範圍外）。
- **Skill 是否能自動判斷**：Yes（比例）；缺失機制無法判斷，只能提醒。

### 12. 想用概似比檢定比較 GEE 模型【MVP】

- **狀況**：使用者要求 GEE 的 deviance、LR 檢定、AIC。
- **為什麼要注意**：GEE 沒有完整的機率分配，所以沒有概似函數，也沒有 deviance（§9.2.4）。
- **標示與做法**：❌；改用 robust SE 的 Wald 檢定（`anova(geeglm)` 或 `waldts`）。GLMM 可以用 LR 檢定（§10.1.6）。
- **Skill 是否能自動判斷**：Yes。

### 13. GLMM 的估計不穩定【MVP】

- **狀況**：增加 quadrature 點數後，估計值或 SE 在前幾位有效數字仍然改變；或出現不收斂的訊息。
- **為什麼要注意**：GLMM 的概似函數要用數值積分近似，點數太少時近似不準（§10.1.5）。
- **標示與做法**：程式自動用 50 點與 100 點配適並比較；任何固定效果或 σ̂ 的差異超過 0.0005（小數第 3 位的半個單位）時 ⚠️，報告 100 點的結果並說明。不收斂時 ⚠️，不報告該模型的推論。
- **實例**：課本墮胎例（σ̂ = 8.75）用 25 點時 σ̂ = 9.34、sit1 = 0.841，100 點才是課本的 8.75、0.835。σ 越大越需要多點數。
- **Skill 是否能自動判斷**：Yes。

### 14. 檢定隨機效果 σ = 0【MVP】

- **狀況**：使用者問「需不需要隨機效果」「個體差異顯著嗎」。
- **為什麼要注意**：σ = 0 在參數空間的邊界，Wald 檢定（σ̂/SE）不適用；LR 統計量的分配是 ½ 在 0、½ 為 χ²₁（§10.1.6）。
- **標示與做法**：✅ 用 LR 檢定，**P 值 = χ²₁ 右尾機率的一半**；不要用 Wald。
- **Skill 是否能自動判斷**：Yes。

### 15. 大部分叢集的回答都相同【文字提醒】

- **狀況**：例如 1850 人中 1595 人三種情境的回答都一樣（§10.2.3）。
- **為什麼要注意**：表示個體差異很大，σ̂ 會很大；GLMM 的效果會比 GEE 大很多（課本例子約 5–6 倍），SE 也一樣大。這不是錯誤（§10.1.4）。
- **做法**：報告「所有回答都相同的叢集」比例；並排比較時一定要解釋。
- **Skill 是否能自動判斷**：Yes。

### 16. 完全分離【MVP】

- **狀況**：某個解釋變數的值能完美區分 0 與 1。
- **為什麼要注意**：估計值其實是無限大，係數與 SE 沒有意義（§5.3）。
- **標示與做法**：⚠️，沿用 Part 2 的 `SEPARATION` 處理方式。
- **Skill 是否能自動判斷**：Yes。

### 17. 比例勝算假設（有序 GEE）【文字提醒】

- **狀況**：累積 logit 模型假設每個切點的效果相同。
- **做法**：說明這個假設；第一版不做正式檢定（§6.3.2、§9.3.1）。
- **Skill 是否能自動判斷**：No。

## D. 解釋與用語（每次都要遵守）

### 18. 整體平均 vs 同一個人【MVP】

- GEE 的效果一律寫「**整體來說**／在母體中……」；GLMM 的效果一律寫「**對同一個人**（隨機效果相同時）……」。
- McNemar 的條件勝算比 n₁₂/n₂₁ 是**個體層次**的；邊際勝算比（兩個邊際比例的勝算比）是**整體層次**的。兩者不可混稱（§8.2.4、§10.1.4）。
- GEE 與 GLMM 數字不同時：說明兩者回答不同問題；在邏輯連結下，個體差異（σ）越大，整體平均的效果越接近 0（§10.1.4，Figure 10.1）。**不可以說其中一個算錯。**

### 19. naive SE vs robust SE【MVP】

- GEE 一律報告 robust SE。
- 若同時顯示 naive SE，要說明：naive SE 假設 working correlation 正確，robust SE 不需要這個假設（§9.2.2）；正相關時，叢集間效果的 robust SE 通常比把資料當獨立時大，叢集內效果則較小（§9.2.3）。

### 20. 沿用 Part 1 的用語規則

| 情況 | 要這樣寫 | 不可以這樣寫 |
|---|---|---|
| P < 0.05 | 「有證據顯示……」，並用效果量與信賴區間說明大小 | 「差很多」「高度相關」 |
| P ≥ 0.05 | 「證據不足，無法確定……」，並說明信賴區間多寬 | 「沒有差別」「沒有效果」 |
| 觀察性資料 | 「有關聯」「比較高」 | 「造成」「導致」 |
| 勝算比 = 2 | 「勝算是 2 倍」 | 「機率是 2 倍」 |

只有使用者確認是**隨機分派的實驗**時，才可以用因果用語（例如 §9.3.1 的失眠試驗）。
